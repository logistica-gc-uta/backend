All ADMIN operations use JWT + ADMIN guard. Controller-scoped `ShopHttpExceptionFilter` wraps even guard and DTO errors as `{error:{code,message,details,requestId}}`. No DELETE product/category; legacy `/products` and existing order routes remain untouched. Category deactivation takes its category lock first, then product locks in sorted IDs (using the shared `lockInventoryProduct`). Product category/publication edits lock the target category before the product; stock and price changes set `updatedAt` from the pinned DB clock. Public and ADMIN lists, detail, and category reads pin a Prisma 8 `client.transaction` callback with `tx.query`/`tx.orm` and set PostgreSQL `READ ONLY REPEATABLE READ` before the first read. Within that one MVCC snapshot, list IDs/window totals/out-of-range count fallback, batched ORM product+category+images+upload hydration and one grouped category-count query agree even if publication/category/gallery changes commit concurrently. Pages hydrate at most 48 public / 50 ADMIN rows, not one query per image/product. Price writes use `centsToLegacyPrice` and `BigInt(priceCents)` in the same transaction; no Float filters. Gallery records and uploads are read only here. A category deactivation hides products without modifying their publication flag or historical purchases. Image URLs in test fixtures are local synthetic example.test references, not Cloudinary integration evidence.
